Cenário 1: Datacenter Corporativo + Power BI Gateway

Isolamento total de rede, consumo direto do QueueMetrics e tráfego seguro de Power BI via TLS de saída.

✔ Recomendado pela Engenharia & Segurança

Por que este é o Cenário Vencedor?

  • ✔ Segurança 100% Satisfeita: O PostgreSQL não tem IP público. Os tokens de clientes e credenciais ficam guardados no perímetro protegido do Datacenter corporativo.
  • ✔ QueueMetrics Resolvido: Por estar no mesmo DC, a comunicação é interna de servidor para servidor, sem passar pelo captive portal da Fortinet do escritório.
  • ✔ Power BI Atualizado com Segurança: O Power BI Gateway só faz chamadas de saída (Outbound Azure Relay). Não exige abrir portas de firewall para fora.
  • ✔ Custo Mínimo: Utiliza recursos já existentes no Datacenter (sem custo extra com VPNs caras por túnel na Azure).

Requisitos a Solicitar à Infra/Segurança

  • 1. Criação de 2 VMs no DC: 1 Linux (4 vCPU, 8-16GB RAM, 100GB SSD p/ DW e pipelines) e 1 Windows Server (2-4 vCPU, 8GB RAM p/ Power BI Gateway).
  • 2. Liberação de rota interna entre a VM Linux e o servidor do QueueMetrics.
  • 3. Contas de serviço / túnel SSH automatizado para os Jump Points dos clientes que têm acesso restrito.
Cenário 0: Arquitetura Atual na VPS (Gargalos & Riscos)

Banco de dados público, impossibilidade de coletar clientes privados e perda de telefonia.

⚠ Inseguro & Limitado

Principais Vulnerabilidades

  • ✖ Porta 5432 Exposta: O banco está sujeito a ataques de negação de serviço (DoS), ataques de dicionário e exploração de CVEs do Postgres.
  • ✖ Exposição da Infraestrutura dos Clientes: Mapeamentos de topologia de rede Zabbix e credenciais na VPS violam cláusulas de segurança contratuais.
  • ✖ Cegueira Operacional: Clientes com redes fechadas e os dados de telefonia do QueueMetrics não são integrados no DW.
Cenário 2: Nuvem Híbrida (Azure + Trânsito via DC)

Evita o custo de dezenas de VPNs na nuvem concentrando a saída pela VPN central do Datacenter.

Estratégia Cloud Otimizada

Como contornar o problema de custo na Azure

O motivo de terem achado as VPNs da Azure caras é porque cotaram 1 VPN Gateway para cada cliente.

  • ✦ Trânsito via Datacenter: Mantém-se apenas 1 único túnel VPN ligando o Datacenter à VNet da Azure. O Datacenter faz o roteamento para os clientes.
  • ✦ Atenção ao Custo Residual: Ainda assim, haverá custo mensal de VM/PaaS do PostgreSQL na nuvem (~$50 - $120/mês) + custo de tráfego de saída (Egress).
Cenário 3: Desktops no Escritório ("Shadow IT")

Alternativa paliativa utilizando computadores físicos locais.

Apenas Contingência Temporária

Por que evitar transformar Desktops em Servidores?

  • ✖ Sem Alta Disponibilidade: Falta de gerador/no-break robusto, risco de limpeza de escritório puxar cabos ou reiniciar computadores.
  • ✖ QueueMetrics bloqueado: A rede do escritório exige autenticação no navegador via Fortinet captive portal, interrompendo scripts automáticos a cada expiração de sessão.
  • ✖ Reprovação por Auditoria: Times de Segurança barram hardware de usuário rodando bancos de dados de produção corporativos.

Como Alinhar com Cada Equipe na Reunião

Segurança da Informação

"Com o Cenário 1, eliminamos a porta 5432 aberta na internet. Tokens de clientes e topologias Zabbix nunca saem do perímetro corporativo. O Power BI conecta via Gateway por canal de saída criptografado (TLS 443), sem abrir nenhuma porta de entrada no firewall."

Engenharia de Dados

"Ganhamos acesso direto e sem captive portal ao banco do QueueMetrics no Datacenter. Conseguiremos automatizar a ingestão horária dos 20 GB com estabilidade e podemos negociar contas de serviço nos Jump Points dos clientes com apoio da infra."

Equipe de BI

"O Power BI On-premises Data Gateway é o padrão oficial corporativo recomendado pela Microsoft. As atualizações de hora em hora passam a ter alta confiabilidade, sem quedas causadas por instabilidade de VPS ou reinicializações locais."
